# 陳腐化したリポジトリ資産を削除するときの確認

未参照・陳腐化した設定、スクリプト、ドキュメントなどを削除する PR では、削除理由だけでなく **リポジトリ内の参照がないと判断した根拠** を PR 本文へ残します。

## PR に残す内容

- 検索したパスや範囲（例: `src/`, `tests/`, `e2e/`, `scripts/`, `.github/workflows/`, `docs/`）
- 検索したファイル名、設定キー、コマンド名などの識別子
- 参照が 0 件だったこと、または削除と同時に更新する参照先
- 履歴ドキュメントや生成物だけを除外した場合は、その除外理由

## 外部依存との区別

リポジトリ内の参照が 0 件でも、外部ツールや手元の運用コマンドが対象ファイルを読む可能性までは否定できません。既知の外部利用がある、または外部利用の可能性を確認する必要がある場合は、リポジトリ内検索の結果と分けて PR / Issue に明記します。

外部依存を確認できない状態で「未使用」と断定せず、確認が必要な項目はフォローアップとして残します。
