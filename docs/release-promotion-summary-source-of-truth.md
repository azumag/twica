# preview → main 昇格時のリリース要約契約

## 通知の正本

同一リポジトリの `preview` から `main` へ昇格する PR では、PR 本文の最初の `## このリリースで変わること` セクションを、人間向けリリース要約の正本として扱う。

`.github/workflows/notify-discord-main-merge.yml` は、このセクションを HTML コメント除去・リンク表記のサニタイズ後に Discord 通知へ再利用する。昇格 PR の validate job は、同セクションに意味のある本文が存在することを確認する。

## 実差分との関係

通知生成時に `preview..main` の実差分や、昇格に含まれる component PR 一覧を GitHub API から再構築して要約本文と自動照合することはしない。

これは、機械的な差分列挙ではなく、昇格 PR 上でレビューされた利用者向け説明をそのまま通知するための設計である。その代わり、実際の昇格内容と要約がずれた場合は、マージ前に PR 本文を更新する必要がある。validate job が保証するのは要約が空でないことまでで、要約内容と実差分の意味的な一致までは検証しない。

## 昇格 PR 以外

`main` にマージされた PR でも通知 workflow 自体は動作するが、同一リポジトリの `preview → main` だけを canonical な昇格経路として扱う。

- 同一リポジトリからの direct-to-main PR は、対象セクションがあれば利用し、無ければ PR タイトルへフォールバックする。
- fork 由来 PR は PR 本文を通知入力として信頼せず、PR タイトルへフォールバックする。

この文書は現行の通知入力契約を記録するものであり、workflow の検証ロジック、通知内容、ブランチ保護、マージ条件は変更しない。
