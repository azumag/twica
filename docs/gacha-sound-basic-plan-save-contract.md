# basicプランのガチャ効果音保存契約

Issue #991 で追跡している basic プランのガチャ効果音ルールについて、現在の保存契約と後方互換ミラーの責務を記録する。この文書は現行挙動の説明だけを目的とし、プラン権限やUIの仕様変更は行わない。

## 保存時のプランゲート

`POST /api/streamer/settings` では、支援プラン以上は正規化後の `gachaSoundRules` をそのまま保存する。basic プランでは、既存ルールを不用意に失わないことを優先しつつ、新規追加分だけを制限する。

- 更新前から存在するルールは保持でき、`url` / `label` / `enabled` の編集も許可される。
- 既存ルールと同じ `id` を使って `targetType` / `rarity` / `rewardId` / `rewardName` を変更しようとした場合、そのプラン限定フィールドだけを保存済みの値へ戻す。
- 新規ルールは、保持対象に `targetType: "all"` が無い場合に限り、`all` ルールを1件だけ追加できる。
- 制限で送信内容の一部を落とした場合は、保存自体を失敗させず `gachaSoundRulesPremiumRequired: true` を返し、クライアントは実際に保存された `gachaSoundRules` へ同期する。

この契約は「basic に戻った利用者が既存の高度なルールを持っている場合、それを無関係な設定保存で消さない」ためのデータ保護を含む。既存ルールをどこまで編集可能にするかという収益・プロダクト方針は Issue #991 の判断事項として別に扱う。

## 現在値の読み取りに失敗した場合

basic プランのゲートは、送信ルールが新規か既存かを判断するため、保存前に現在の `gacha_sound_rules` を読む。

- `gacha_sound_rules` 列そのものが未デプロイで、列欠落として判定できる場合だけ `[]` とみなす。列が存在しないため、温存すべき既存ルールも存在しないデプロイ窓向けの縮退である。
- 接続断・タイムアウトなど、列欠落以外の読み取り失敗は `[]` にせずリクエスト全体を失敗させる。現在値を推測して保存を続けると、既存ルールを新規扱いして削る可能性があるためである。

## 旧オーバーレイ向けミラー

`streamers.gacha_sound_url` / `gacha_sound_enabled` は、複数ルールを理解しない旧オーバーレイクライアント向けの後方互換ミラーである。複数ルール機能全体の有効フラグではない。

保存時のミラー値は、**プランゲートと正規化を通過して実際に保存するルール集合**から導出する。

- 有効な `targetType: "all"` ルールがあれば、そのURLを `gacha_sound_url` に保存し、`gacha_sound_enabled` を `true` にする。
- 有効な `all` ルールが無ければ `gacha_sound_url = null`、`gacha_sound_enabled = false` とする。
- レアリティ別・報酬別ルールだけを旧ミラーへ流用しない。限定ルールを「全カードで鳴る音」として旧クライアントへ誤配信しないためである。

ルール対応クライアントは `gachaSoundRules` 自体を使って再生対象を決める。ルールが存在する場合、旧 `gacha_sound_enabled` ミラーを複数ルール機能全体の再生ゲートとして扱わない。

## この文書で決めないこと

以下は Issue #991 の別フォローアップであり、この契約文書の収束条件には含めない。

- basic プランで既存ルールの「差し替え」をどのUIで許可するか
- 支援プラン解約後も既存の高度なルール編集を許可し続けるか
- `rewardName` をプラン限定フィールドとして扱い続けるか
- DBエラー分類や読み取りラウンドトリップの最適化
- UIコピーや部分成功メッセージの見直し
