# Issue #55: Critical Security - Missing CSRF Protection on State-Changing API Routes

## 概要

アプリケーションは現在セッションベースの認証のみを使用しており、CSRF（Cross-Site Request Forgery）保護が実装されていません。これにより、すべての状態変更操作がCSRF攻撃に対して脆弱です。

## 問題分析

### 現在の実装

現在のセッション管理（`src/lib/session.ts`, `src/app/api/auth/twitch/callback/route.ts`）:

```typescript
// OAuth callbackでセッションクッキーを設定
cookieStore.set(COOKIE_NAMES.SESSION, sessionData, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'lax',  // CSRFトークンとの併用で多層防御を実現
  path: '/',
  maxAge: SESSION_CONFIG.MAX_AGE_SECONDS,
})
```

**問題点:**

1. **SameSite='lax'の脆弱性**:
   - `'lax'`設定では、トップレベルナビゲーション時のGETリクエストでクッキーが送信される
   - POSTリクエストはSameSite制限で保護されるが、完全ではない
   - OAuthフローでは`'lax'`が必要だが、これがCSRFの脆弱性を生む

2. **CSRFトークンの欠如**:
   - すべてのPOST/PUT/DELETE APIルートはセッションクッキーのみで認証
   - カスタムヘッダーの検証がない
   - リクエストのオリジンを検証していない

3. **影響を受けるエンドポイント**:
   - `/api/upload` - ファイルアップロード
   - `/api/cards` - カード作成/更新/削除
   - `/api/gacha` - ガチャ実行
   - `/api/battle/start` - バトル開始
   - `/api/streamer/settings` - 配信者設定
   - `/api/user-cards` - ユーザーカード管理

### 攻撃シナリオ

SameSite='lax'はクロスサイトPOSTリクエストでCookieが送信されない保護機能を提供しますが、CSRFトークンとの併用で防御の深層化を実現する必要があります。

攻撃者が以下のような悪意のあるサイトを作成できます:

```html
<!-- 攻撃者のサイト -->
<form action="https://twica.app/api/battle/start" method="POST">
  <input type="hidden" name="userCardId" value="victim-card-id">
  <button>Click to win prize!</button>
</form>

<script>
  // 自動送信
  document.forms[0].submit();
</script>
```

SameSite='lax'の保護機能:
- クロスサイトPOSTリクエストではCookieが送信されないため、この攻撃はブロックされる
- ただし、トップレベルナビゲーションでのGETリクエストは許可されるため、完全な保護ではない
- CSRFトークンとの併用で多層防御を実現し、あらゆる攻撃ベクトルに対応する

ユーザーがログイン状態でこのサイトにアクセスした場合:
- SameSite='lax'によりPOSTリクエストでCookieは送信されない
- CSRFトークン検証により追加の保護レイヤーが提供される
- 攻撃者の意図しないバトル実行は防止される

## 機能要件

1. **CSRFトークン生成**:
   - ユーザーごとにユニークなCSRFトークンを生成
   - セッションとトークンを関連付けて保存
   - 暗号学的に安全な乱数を使用

2. **CSRFトークン配布**:
   - トークンをセッションに保存
   - APIエンドポイント経由でクライアントに配布
   - クライアントがリクエストに含める

3. **CSRFトークン検証**:
   - すべてのPOST/PUT/DELETEリクエストでトークンを検証
   - カスタムヘッダー（`X-CSRF-Token`）を使用
   - トークン不一致の場合は403エラーを返す

4. **セキュアなトークン管理**:
   - セッションごとに一意のトークン
   - トークンの有効期限を管理
   - ログアウト時にトークンを無効化

## 非機能要件

1. **セキュリティ**:
   - 暗号学的に強力な乱数生成器を使用
   - トークン推測攻撃を防ぐため、十分なエントロピーを持つ
   - タイミング攻撃に対して安全な比較

2. **可用性**:
   - 既存のOAuthフローを維持
   - すべての正当なリクエストが正常に動作
   - エラーメッセージは攻撃者に情報を漏らさない

3. **パフォーマンス**:
   - トークン検証のオーバーヘッドを最小化
   - キャッシュ戦略を検討（ただし、セキュリティを優先）

4. **可観測性**:
   - CSRF検証エラーをloggerとSentryに記録
   - 不審なリクエストパターンを検知

## 受け入れ基準

1. **CSRF保護の実装**:
   - すべてのPOST/PUT/DELETE APIルートでCSRFトークン検証が行われる
   - トークンがセッションに正しく保存される
   - トークン配布APIが動作する

2. **セキュリティ**:
   - CSRF攻撃が防止されることをテストで検証
   - トークンが推測不可能であること
   - トークン不一致が適切に検知される

3. **既存機能の互換性**:
   - OAuthフローが正常に動作
   - すべての機能がCSRF保護下で動作
   - エラーメッセージが適切

4. **テスト**:
   - CSRF保護のユニットテストが存在
   - 統合テストがパス
   - 手動テストでCSRF攻撃が防止されることを確認

## 設計方針

### アーキテクチャ決定

**選択: Custom Request Header Pattern**

選定理由:
1. SPA（Single-Page Application）に最適
2. 既存のOAuthフローに影響を与えない
3. 実装が比較的シンプル
4. SameSiteクッキーの制限を受けない

### コンポーネント設計

#### 1. CSRFトークン管理モジュール

**新規ファイル**: `src/lib/csrf.ts`

```typescript
import { cookies } from 'next/headers'
import { crypto } from 'node:crypto'
import { logger } from './logger'
import { reportSecurityError } from './sentry/error-handler'
import { COOKIE_NAMES } from './constants'

const CSRF_TOKEN_LENGTH = 32 // 256 bits
const CSRF_HEADER = 'X-CSRF-Token'
const CSRF_ERROR_MESSAGE = 'Invalid CSRF token'

/**
 * CSRFトークンを生成
 */
function generateCSRFToken(): string {
  return crypto.randomBytes(CSRF_TOKEN_LENGTH).toString('hex')
}

/**
 * セッションにCSRFトークンを保存
 */
export async function setCSRFToken(): Promise<string> {
  const cookieStore = await cookies()
  const token = generateCSRFToken()

  // セッションからユーザーIDを取得
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value
  if (!sessionCookie) {
    throw new Error('No session found')
  }

  const session = JSON.parse(sessionCookie)
  const userId = session.twitchUserId

  // ユーザーごとのキーでRedisまたはメモリに保存
  // 今回は実装を簡素化するため、セッション自体にCSRFトークンを含める
  const updatedSession = {
    ...session,
    csrfToken: token,
  }

  cookieStore.set(COOKIE_NAMES.SESSION, JSON.stringify(updatedSession), {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 7 * 24 * 60 * 60, // 7 days
  })

  logger.info(`CSRF token generated for user ${userId}`)
  return token
}

/**
 * CSRFトークンを検証
 */
export async function validateCSRFToken(
  request: NextRequest
): Promise<{ valid: boolean; error?: string }> {
  const cookieStore = await cookies()
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value

  if (!sessionCookie) {
    return { valid: false, error: 'No session found' }
  }

  const session = JSON.parse(sessionCookie)
  const sessionToken = session.csrfToken

  if (!sessionToken) {
    return { valid: false, error: 'No CSRF token in session' }
  }

  const requestToken = request.headers.get(CSRF_HEADER)

  if (!requestToken) {
    return { valid: false, error: 'CSRF token missing in request' }
  }

  // 定数時間比較（タイミング攻撃対策）
  const isValid = crypto.timingSafeEqual(
    Buffer.from(sessionToken),
    Buffer.from(requestToken)
  )

  if (!isValid) {
    logger.warn('CSRF token validation failed', {
      userId: session.twitchUserId,
      ip: request.headers.get('x-forwarded-for'),
    })

    // Sentryに報告
    reportSecurityError(new Error('CSRF token mismatch'), {
      action: 'csrf_validation',
      userId: session.twitchUserId,
    })

    return { valid: false, error: CSRF_ERROR_MESSAGE }
  }

  return { valid: true }
}

/**
 * CSRFトークン取得API用ヘルパー
 */
export async function getCSRFToken(): Promise<string | null> {
  const cookieStore = await cookies()
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value

  if (!sessionCookie) {
    return null
  }

  const session = JSON.parse(sessionCookie)
  return session.csrfToken || null
}
```

#### 2. CSRFトークン取得APIエンドポイント

**新規ファイル**: `src/app/api/csrf-token/route.ts`

```typescript
import { NextResponse } from 'next/server'
import { setCSRFToken } from '@/lib/csrf'
import { getSession } from '@/lib/session'
import { handleApiError } from '@/lib/error-handler'
import { ERROR_MESSAGES } from '@/lib/constants'

export async function GET() {
  try {
    // 認証済みユーザーのみがトークンを取得可能
    const session = await getSession()

    if (!session) {
      return NextResponse.json(
        { error: ERROR_MESSAGES.UNAUTHORIZED },
        { status: 401 }
      )
    }

    // CSRFトークンを生成して返す
    const token = await setCSRFToken()

    return NextResponse.json({ csrfToken: token })
  } catch (error) {
    return handleApiError(error, 'CSRF Token API')
  }
}
```

#### 3. CSRF検証ミドルウェア

**新規ファイル**: `src/lib/middleware/csrf.ts`

```typescript
import { NextRequest, NextResponse } from 'next/server'
import { validateCSRFToken } from '@/lib/csrf'
import { ERROR_MESSAGES } from '@/lib/constants'

/**
 * CSRFトークンを検証するミドルウェア
 * POST/PUT/DELETEリクエストに対して適用
 */
export async function withCSRFProtection(
  handler: (request: NextRequest) => Promise<NextResponse>
): Promise<NextResponse> {
  return async (request: NextRequest) => {
    const method = request.method.toUpperCase()

    // POST/PUT/DELETEのみ検証
    if (['POST', 'PUT', 'DELETE'].includes(method)) {
      const validation = await validateCSRFToken(request)

      if (!validation.valid) {
        return NextResponse.json(
          { error: ERROR_MESSAGES.FORBIDDEN },
          { status: 403 }
        )
      }
    }

    return handler(request)
  }
}
```

#### 5. クライアント側の実装

**新規ファイル**: `src/lib/client/csrf.ts`

```typescript
/**
 * CSRFトークンを取得
 */
export async function fetchCSRFToken(): Promise<string> {
  const response = await fetch('/api/csrf-token')
  if (!response.ok) {
    throw new Error('Failed to fetch CSRF token')
  }
  const data = await response.json()
  return data.csrfToken
}

/**
 * CSRF保護されたfetchラッパー
 */
export async function fetchWithCSRF(
  url: string,
  options: RequestInit = {}
): Promise<Response> {
  const method = (options.method || 'GET').toUpperCase()

  // POST/PUT/DELETEの場合、CSRFトークンを追加
  if (['POST', 'PUT', 'DELETE'].includes(method)) {
    let csrfToken = localStorage.getItem('csrfToken')

    if (!csrfToken) {
      csrfToken = await fetchCSRFToken()
      localStorage.setItem('csrfToken', csrfToken)
    }

    options.headers = {
      ...options.headers,
      'X-CSRF-Token': csrfToken,
    }
  }

  return fetch(url, options)
}
```

**修正ファイル**: 各コンポーネントのfetch呼び出し

### トレードオフ

#### メリット

1. **セキュリティ向上**:
   - CSRF攻撃を効果的に防止
   - ユーザーの不正利用を防ぐ
   - OWASP推奨のベストプラクティスに準拠

2. **実装の簡潔さ**:
   - 追加のデータベースが不要
   - 既存のセッション構造を利用
   - クライアント側の実装が簡単

3. **OAuthフローとの互換性**:
   - SameSite='lax'を維持
   - OAuthコールバックが正常に動作

#### デメリット

1. **クライアント側の修正**:
   - すべてのfetch呼び出しを修正する必要がある
   - 多数のファイルに変更が必要

2. **セッションサイズの増加**:
   - CSRFトークンがセッションに含まれるため、サイズが増加
   - 32文字（256ビット）の追加

3. **トークン更新ロジック**:
   - セッション更新時にトークンも更新する必要がある
   - ログアウト時にトークンを無効化

### リスク

1. **実装ミスのリスク**:
   - 一部のAPIルートで検証を忘れる可能性
   - 回避策: ESLintルールやTypeScriptのデコレータで強制

2. **パフォーマンスへの影響**:
   - すべてのリクエストでトークン検証が追加される
   - 回避策: キャッシュ戦略の検討（ただし、セキュリティを優先）

3. **クライアント側の複雑性**:
   - fetchWithCSRFラッパーの導入が必要
   - 回避策: 開発者ドキュメントと例を提供

#### ユニットテスト

**新規ファイル**: `tests/unit/csrf.test.ts`

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { generateCSRFToken, validateCSRFToken } from '@/lib/csrf'

describe('CSRF Protection', () => {
  describe('generateCSRFToken', () => {
    it('should generate a token of correct length', () => {
      const token = generateCSRFToken()
      expect(token).toHaveLength(64) // 32 bytes * 2 (hex)
    })

    it('should generate unique tokens', () => {
      const token1 = generateCSRFToken()
      const token2 = generateCSRFToken()
      expect(token1).not.toBe(token2)
    })
  })

  describe('validateCSRFToken', () => {
    it('should validate matching tokens', async () => {
      const token = generateCSRFToken()
      // Mock request with matching token
      const request = new Request('https://example.com', {
        headers: { 'X-CSRF-Token': token }
      })
      const result = await validateCSRFToken(request)
      expect(result.valid).toBe(true)
    })

    it('should reject missing token', async () => {
      const request = new Request('https://example.com')
      const result = await validateCSRFToken(request)
      expect(result.valid).toBe(false)
    })

    it('should reject mismatched tokens', async () => {
      const request = new Request('https://example.com', {
        headers: { 'X-CSRF-Token': 'wrong-token' }
      })
      const result = await validateCSRFToken(request)
      expect(result.valid).toBe(false)
    })
  })
})
```
