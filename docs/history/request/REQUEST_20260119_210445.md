### 質問

2. `CSRF_CONFIG.ALLOWED_ORIGINS` の定義は必要ですか？

## 質問3: HttpOnly Cookie Pattern vs Double Submit Cookie Pattern

### 問題点

現在の実装（`src/lib/csrf.ts`）では、以下の2つのパターンが混在しています：

1. **HttpOnly Cookie Pattern**:
   - トークンをhttpOnly cookieに保存（line 108）
   - 検証時にcookieからトークンを取得（line 194）

2. **Double Submit Cookie Pattern**:
   - Originヘッダーの検証（line 153-191）
   - トークン長の検証（line 206-211）

### 質問

1. どちらのパターンを採用するべきですか？
   - 設計書ではHttpOnly Cookie Patternを選択していますが、実装ではOriginヘッダーの検証も実装されています

2. Originヘッダーの検証は必要ですか？
   - HttpOnly Cookie Patternでは、cookieからのトークン取得だけで十分ではありませんか？

3. どちらのパターンが最適かを判断する基準を教えてください
