## Critical Issuesの修正

### C1: Session Update May Lose Data

**問題:** shallow copyを使用しており、継承されたプロパティが失われる可能性があります。

**修正場所:** src/lib/csrf.ts:106-110

**修正前:**
```typescript
const updatedSession = {
  ...session,
  csrfTokenHash: tokenHash,
  version: session.version + 1,
}
```

**修正後:**
```typescript
const updatedSession = parseSession(JSON.stringify({
  ...JSON.parse(sessionCookie),
  csrfTokenHash: tokenHash,
  version: session.version + 1,
}))
```

**効果:** すべてのプロパティが確実に保持されるよう、JSON.stringify/parseによるディープコピーを実装

### C2: Race Condition in Idempotent Token Generation

**問題:** `session.csrfTokenHash`のチェックとcookie取得の間でTOCTOU脆弱性があります。

**修正場所:** src/lib/csrf.ts:58-61

**修正前:**
```typescript
if (session.csrfTokenHash) {
  const existingToken = getCSRFTokenFromCookie(cookieStore)
  if (existingToken) {
    return existingToken
  }
}
```

**修正後:**
```typescript
const existingToken = getCSRFTokenFromCookie(cookieStore)
if (session.csrfTokenHash && existingToken) {
  return existingToken
}
```

**効果:** アトミックにチェックと取得を行い、TOCTOU脆弱性を解消

### C3: clearCSRFToken Leaves Undefined Properties

**問題:** `delete`演算子が`undefined`値を持つプロパティを作成します。

**修正場所:** src/lib/csrf.ts:280-286

**修正前:**
```typescript
const updatedSession = { ...session }
delete updatedSession.csrfTokenHash
```

**修正後:**
```typescript
const { csrfTokenHash: _, ...updatedSession } = session
```

**効果:** destructuringを使用してプロパティを完全に削除

## High Priority Issuesの修正

### H1: parseSession Called Multiple Times Per Request

**問題:** 各リクエストでparseSessionが複数回呼ばれています（setCSRFToken, validateCSRFToken, clearCSRFToken）。

**修正場所:** src/lib/csrf.ts:57, 77, 142, 280

**修正内容:** Reactの`cache`関数を使用してリクエストスコープのキャッシュを実装

**実装:**
```typescript
import { cache } from 'react'

const session = cache(() => parseSession(sessionCookie))()
```

**影響箇所:**
- `setCSRFTokenWithRetry`: 初回パース (line 57)
- `setCSRFTokenWithRetry`: バージョンチェック用パース (line 77)
- `validateCSRFToken`: 検証用パース (line 142)
- `clearCSRFToken`: クリア用パース (line 280)

**効果:** リクエストごとに1回だけparseSessionが呼ばれるようになり、パフォーマンス向上

## Double Submit Cookie Patternへの移行

**日時:** 2026-01-19 23:00
**目的:** CSRF保護の実装をHttpOnly Cookie PatternからDouble Submit Cookie Patternに変更

### 実装内容

#### 1. src/lib/client/csrf.tsの作成

Double Submit Cookie Patternのクライアントサイド実装を作成しました。

```typescript
/**
 * CookieからCSRFトークンを取得
 */
function getCSRFTokenFromCookie(): string | null {
  const match = document.cookie.match(/csrf_token=([^;]+)/)
  return match ? match[1] : null
}

/**
 * CSRF保護されたfetchラッパー
 */
export async function fetchWithCSRF(
  url: string,
  options: RequestInit = {}
): Promise<Response> {
  const method = (options.method || 'GET').toUpperCase()

  if (['POST', 'PUT', 'DELETE'].includes(method)) {
    const csrfToken = getCSRFTokenFromCookie()
    if (!csrfToken) {
      throw new Error('CSRF token not found in cookie')
    }
    options.headers = {
      ...options.headers,
      'X-CSRF-Token': csrfToken,
    }
  }

  return fetch(url, options)
}
```

#### 3. src/lib/csrf.tsの更新

validateCSRFToken関数を更新し、X-CSRF-Tokenヘッダーからトークンを取得するように変更しました。

**修正前:**
```typescript
// Cookieからトークンを取得（HttpOnly Cookie Pattern）
const requestToken = getCSRFTokenFromCookie(cookieStore)

if (!requestToken) {
  logger.warn('CSRF validation failed: CSRF token missing in cookie', {
    userId: session.twitchUserId,
    endpoint: sanitizeURL(request.url),
  })

}
```

**修正後:**
```typescript
// X-CSRF-Tokenヘッダーからトークンを取得（Double Submit Cookie Pattern）
const requestToken = request.headers.get(CSRF_CONFIG.HEADER_NAME)

if (!requestToken) {
  logger.warn('CSRF validation failed: CSRF token missing in request', {
    userId: session.twitchUserId,
    endpoint: sanitizeURL(request.url),
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }

```
