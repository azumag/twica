# レビュー対応によるCSRF保護機能の修正

## 概要

レビュー結果（docs/REVIEW.md）に基づいて、CSRF保護機能のセキュリティと堅牢性を強化しました。

---

## 修正内容

### 優先度: 高

#### 1. CSRF_SIGNING_KEYの必須化

**ファイル**: `src/lib/csrf.ts`

**問題点**: フォールバック値が設定されており、セキュリティリスクがある

**修正内容**:
- フォールバック値を削除
- 環境変数未設定時にエラーを投げる

**修正前**:
```typescript
const SIGNING_KEY = process.env.CSRF_SIGNING_KEY || 'default-key-change-in-production'
```

**修正後**:
```typescript
const SIGNING_KEY = process.env.CSRF_SIGNING_KEY
if (!SIGNING_KEY) {
  throw new Error('CSRF_SIGNING_KEY environment variable is required')
}
```

---

#### 2. IPアドレスのハッシュ化

**ファイル**: `src/lib/csrf.ts`

**問題点**: IPアドレスを直接記録すると、プライバシー規制（GDPRなど）に抵触する可能性がある

**修正内容**:
- IPアドレスをSHA-256でハッシュ化して記録
- ハッシュ値の先頭8文字のみを記録

**実装**:
```typescript
const hashIP = (ip: string | null) => {
  if (!ip) return 'unknown'
  return crypto.createHash('sha256').update(ip).digest('hex').substring(0, 8)
}

logger.warn('CSRF validation failed: No session found', {
  ip: hashIP(request.headers.get('x-forwarded-for')),
  userAgent: request.headers.get('user-agent'),
})
```

---

### 優先度: 中

#### 3. URLのサニタイズ

**ファイル**: `src/lib/csrf.ts`

**問題点**: URL全体にクエリパラメータが含まれている可能性があり、情報漏洩のリスクがある

**修正内容**:
- URLをパスのみにサニタイズ

**実装**:
```typescript
const sanitizeURL = (url: string) => {
  try {
    return new URL(url).pathname
  } catch {
    return url
  }
}

logger.warn('...', {
  endpoint: sanitizeURL(request.url),
})
```

---

#### 4. トークン長の検証

**ファイル**: `src/lib/csrf.ts`

**問題点**: トークンの長さを検証していない

**修正内容**:
- `validateCSRFToken` 関数でトークンの長さを検証
- トークンが正しい長さ（64文字）であることを確認

**実装**:
```typescript
if (requestToken.length !== CSRF_CONFIG.TOKEN_LENGTH * 2) {
  logger.warn('CSRF validation failed: Invalid token length', {
    userId: session.twitchUserId,
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
}
```

---

#### 5. バッファ長不一致の安全な処理

**ファイル**: `src/lib/csrf.ts`

**問題点**: `timingSafeEqual` でバッファ長不一致が発生するとエラーがスローされ、情報漏洩のリスクがある

**修正内容**:
- バッファ長を事前に検証
- 長さが不一致の場合は検証失敗として処理

**実装**:
```typescript
const sessionBuffer = Buffer.from(sessionTokenHash)
const requestBuffer = Buffer.from(requestTokenHash)

if (sessionBuffer.length !== requestBuffer.length) {
  logger.warn('CSRF validation failed: Hash length mismatch', {
    userId: session.twitchUserId,
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
}

const isValid = timingSafeEqual(sessionBuffer, requestBuffer)
```

## セキュリティ上の改善

### 1. CSRF_SIGNING_KEYの必須化

- **効果**: 攻撃者がデフォルトキーを知っていても、署名を偽造できない
- **理由**: 本番環境では必ず強力なランダムな鍵を使用する必要がある

### 2. IPアドレスのハッシュ化

- **効果**: プライバシー規制（GDPRなど）への対応
- **理由**: IPアドレスを直接記録すると、個人を特定する情報として扱われる可能性がある

### 3. URLのサニタイズ

- **効果**: クエリパラメータ内の機密情報の漏洩を防止
- **理由**: ログにはエンドポイントのパスのみを記録する

### 4. トークン長の検証

- **効果**: 不正な長さのトークンを早期に検知
- **理由**: バッファオーバーフローや不正なトークンを防ぐ

### 5. バッファ長不一致の安全な処理

- **効果**: タイミング攻撃の可能性を低減
- **理由**: バッファ長が不一致であることを攻撃者に通知しない

---

## 堅牢性の改善

### 1. エラーハンドリング

- バッファ長不一致をエラーではなく検証失敗として処理
- エラーメッセージは汎用的なまま（ERROR_MESSAGES.CSRF_TOKEN_INVALID）

### 2. ログ出力のセキュリティ

- IPアドレスをハッシュ化
- URLをサニタイズ
- エラーの種類に応じて適切なログレベルを使用
