### Phase 1: 基礎コンポーネントの実装 ✅

#### 1. CSRFトークン管理モジュール (`src/lib/csrf.ts`)
- **実装済み**
- HttpOnly Cookie Patternを採用
- 楽観的ロックによる競合状態対策
- セキュリティ配慮のあるログ記録（IPハッシュ化、URLサニタイズ）

主な機能:
- `generateCSRFToken()`: 暗号学的に安全なCSRFトークンを生成（32 bytes = 256 bits）
- `hashToken(token)`: SHA-256ハッシュを生成（CSRF_TOKEN_SALTを使用）
- `setCSRFToken()`: セッションにCSRFトークンのハッシュを保存し、トークン自体はhttpOnly cookieに保存
- `validateCSRFToken(request)`: CSRFトークンを検証（ハッシュ比較）
- `clearCSRFToken()`: CSRFトークンをクリア
- `hashIP(ip)`: IPアドレスをハッシュ化（セキュリティログ用）
- `sanitizeURL(url)`: URLをサニタイズ（セキュリティログ用）

セキュリティ機能:
- **HttpOnly Cookie Pattern**: トークンはhttpOnly cookieに保存され、JavaScriptからアクセス不可
- **ハッシュ比較**: セッションにはトークンのハッシュのみを保存（トークン値の漏洩防止）
- **タイミング攻撃対策**: `timingSafeEqual` による安全な比較
- **楽観的ロック**: セッションにバージョン番号を追加し、競合状態を回避
- **CSRF_TOKEN_SALT 検証**: 本番環境では必須、開発環境では警告ログとデフォルト値

## セキュリティ機能

### 多層防御の実装
1. **第1層**: SameSite='lax' - ブラウザレベルでのクロスサイトPOST阻止
2. **第2層**: HttpOnly Cookie - XSS攻撃時のトークン窃取防止
3. **第3層**: トークン検証 - ハッシュ比較によるトークンの正当性確認
4. **第4層**: セキュリティ配慮のあるログ記録 - IPハッシュ化、URLサニタイズ

### 楽観的ロック
- セッションにバージョン番号を追加
- トークン生成時にバージョンを検証
- バージョンが不一致の場合、リトライ（最大3回、50ms間隔）
- 更新成功時にバージョンをインクリメント

### セキュリティ配慮点
- **トークン生成**: 暗号学的に強力な乱数生成器 (`crypto.randomBytes`)
- **トークン比較**: タイミング攻撃に対して安全な比較 (`crypto.timingSafeEqual`)
- **トークン保存**: ハッシュをセッションに保存、トークン自体はhttpOnly cookieに保存
- **競合状態対策**: 楽観的ロック（バージョン番号による検証）
- **ログ記録**: IPアドレスのSHA-256ハッシュ化、URLのサニタイズ
- **エラーハンドリング**: 詳細なログ記録、汎用的なエラーメッセージ

## アーキテクチャ決定

### HttpOnly Cookie Patternの採用
**理由:**
1. XSS攻撃時にCSRFトークンが窃取されないため、より安全
2. 実装がシンプルでエラーが発生しにくい
3. SameSite='lax' + HttpOnly Cookieで多層防御が実現できる
4. クライアント側での追加実装が不要
5. OAuthフローとの完全な互換性

**トレードオフ:**
- Cookieが1つ追加される（最小限のオーバーヘッド）
