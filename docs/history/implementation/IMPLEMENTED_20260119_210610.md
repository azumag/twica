# レビュー対応によるCSRF保護機能の修正

## 概要

レビュー結果（docs/REVIEW.md）に基づいて、CSRF保護機能をHttpOnly Cookie Patternとして正しく実装する修正を実施しました。

---

## 修正内容

### 優先度: Critical

#### 1. src/lib/csrf.tsの修正

**問題点**: `validateCSRFToken` 関数で `X-CSRF-Token` ヘッダーからトークンを取得していたが、HttpOnly Cookie Patternではcookieからトークンを取得する必要がある

**修正内容**:
- `validateCSRFToken` 関数でcookieからトークンを取得するように修正
- OriginヘッダーおよびRefererヘッダーの検証を削除（HttpOnly Cookie Patternでは不要）
- トークン取得ロジックを `getCSRFTokenFromCookie` 関数を使用するように修正

**修正前**:
```typescript
// X-CSRF-Tokenヘッダーからトークンを取得（Double Submit Cookie Pattern）
const requestToken = request.headers.get(CSRF_CONFIG.HEADER_NAME)

if (!requestToken) {
  logger.warn('CSRF validation failed: CSRF token missing in request', {
    userId: session.twitchUserId,
    endpoint: sanitizeURL(request.url),
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
}
```

**修正後**:
```typescript
// Cookieからトークンを取得（HttpOnly Cookie Pattern）
const requestToken = getCSRFTokenFromCookie(cookieStore)

if (!requestToken) {
  logger.warn('CSRF validation failed: CSRF token missing in cookie', {
    userId: session.twitchUserId,
    endpoint: sanitizeURL(request.url),
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
}
```

### 優先度: High

#### 2. tests/unit/csrf.test.tsの更新

**問題点**: テスト内でヘッダーベースの検証（`'X-CSRF-Token': token`）を行っていたが、HttpOnly Cookie Patternではcookie-based flowに変更する必要がある

**修正内容**:
- テストの説明を修正: "should validate matching tokens from X-CSRF-Token header" → "should validate matching tokens from httpOnly cookie"
- Cookieモックを修正: `COOKIE_NAMES.CSRF_TOKEN` を返すように
- ヘッダーから `X-CSRF-Token` を削除
- トークン長の検証テストをcookie-based flowに変更

**修正前**:
```typescript
const request = new Request('https://example.com', {
  headers: {
    'X-CSRF-Token': token
  }
})
```

**修正後**:
```typescript
const mockCookieStore = {
  get: vi.fn((name) => {
    if (name === COOKIE_NAMES.SESSION) {
      return { value: JSON.stringify(sessionData) }
    }
    if (name === COOKIE_NAMES.CSRF_TOKEN) {
      return { value: token }
    }
    return undefined
  }),
  set: vi.fn(),
}
mockCookies.mockResolvedValue(mockCookieStore as unknown as MockCookieStore)

const request = new Request('https://example.com')
```

**修正内容**:
- テストの説明を修正: "X-CSRF-Token header validation" → "httpOnly cookie validation"

describe('validateCSRFToken - X-CSRF-Token header validation', () => {

## HttpOnly Cookie Patternの正しい実装

### セキュリティ上の特徴

1. **XSS攻撃耐性**: CSRFトークンがhttpOnly cookieに保存され、JavaScriptからアクセス不可
2. **自動送信**: ブラウザが自動的にトークンをリクエストに含める
3. **シンプルな実装**: クライアント側でのトークン操作が不要
4. **エラー発生率低減**: 実装がシンプルなためバグが発生しにくい

### 動作フロー

1. トークン生成時、サーバーはhttpOnly cookieにCSRFトークンを保存
2. セッションにはトークンのハッシュのみを保存（httpOnly）
3. クライアントからのリクエスト時、ブラウザが自動的にcookieを送信
4. サーバーはcookieからトークンを取得し、ハッシュ比較で検証
