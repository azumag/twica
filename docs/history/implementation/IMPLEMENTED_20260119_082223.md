## Issue #55: Critical Security - Missing CSRF Protection on State-Changing API Routes

### 概要
設計書 docs/ARCHITECTURE.md に基づいて、CSRF（Cross-Site Request Forgery）保護を実装しました。

---

## 実装内容

### Phase 1: 基礎コンポーネントの実装

#### 1. src/lib/csrf.ts - CSRFトークン管理モジュール

CSRFトークンの生成、保存、検証を行うモジュールを実装しました。

**実装した関数**:
- `generateCSRFToken()` - 暗号学的に安全な乱数を使用して32バイトのトークンを生成
- `setCSRFToken()` - セッションにCSRFトークンを保存
- `validateCSRFToken(request)` - リクエストのCSRFトークンを検証（タイミング攻撃対策あり）
- `getCSRFToken()` - 現在のセッションからCSRFトークンを取得

**セキュリティ対策**:
- `crypto.randomBytes` による暗号学的に強力な乱数生成
- `crypto.timingSafeEqual` によるタイミング攻撃対策
- エラー時にloggerとSentryに記録

#### 2. src/app/api/csrf-token/route.ts - CSRFトークン取得API

認証済みユーザーがCSRFトークンを取得するためのAPIエンドポイントを実装しました。

**実装内容**:
- GETメソッドのみを許可
- 認証済みユーザーのみアクセス可能
- `setCSRFToken()` を呼び出してトークンを生成
- `{ csrfToken: token }` 形式で返却

#### 3. src/lib/constants.ts - 定数の追加

**追加した定数**:
```typescript
export const CSRF_CONFIG = {
  TOKEN_LENGTH: 32,
  HEADER_NAME: 'X-CSRF-Token',
  ERROR_MESSAGE: 'Invalid CSRF token',
} as const
```

**追加したエラーメッセージ**:
```typescript
CSRF_TOKEN_INVALID: 'Invalid or missing CSRF token',
CSRF_TOKEN_MISSING: 'CSRF token is required for this request',
```

#### 4. src/lib/sentry/error-handler.ts - セキュリティエラー報告関数追加

- `reportSecurityError()` - CSRF検証失敗時のSentry報告関数を追加

### Phase 2: APIルートの保護

#### 1. src/lib/middleware/csrf.ts - CSRF検証ミドルウェア

POST/PUT/DELETEリクエストに対して自動的にCSRFトークンを検証するミドルウェアを実装しました。

**実装内容**:
- 高階関数として実装
- POST/PUT/DELETEリクエストのみ検証対象
- GETリクエストは検証なしで通す
- 検証失敗時に403エラーを返す

#### 2. POST/PUT/DELETE APIルートにCSRF検証を追加

以下のAPIルートにCSRF検証を追加しました：

**保護対象ルート**:
- src/app/api/upload/route.ts (POST)
- src/app/api/battle/start/route.ts (POST)
- src/app/api/streamer/settings/route.ts (POST)
- src/app/api/cards/route.ts (POST)
- src/app/api/cards/[id]/route.ts (PUT, DELETE)
- src/app/api/gacha/route.ts (POST)
- src/app/api/gacha-history/[id]/route.ts (DELETE)

**保護対象外ルート**:
- Twitch Webhook用ルート
- デバッグ用ルート
- 認証前の操作ルート

### Phase 3: クライアント側の実装

#### 1. src/lib/client/csrf.ts - クライアント側CSRFユーティリティ

クライアント側でCSRFトークンを管理し、自動的にリクエストに追加するユーティリティを実装しました。

**実装した関数**:
- `fetchCSRFToken()` - /api/csrf-token からトークンを取得
- `fetchWithCSRF(url, options)` - CSRF保護されたfetchラッパー

**機能**:
- POST/PUT/DELETEリクエストに自動的にCSRFトークンを追加
- localStorageにトークンをキャッシュ
- GETリクエストは通常のfetchとして処理

#### 2. すべてのfetch呼び出しを修正

以下のコンポーネントのfetch呼び出しを `fetchWithCSRF` に置き換えました：

**修正したファイル**:
- src/app/overlay/[streamerId]/page.tsx - /api/gacha (POST)
- src/components/GachaHistorySection.tsx - /api/gacha-history/${historyId} (DELETE)
- src/components/ChannelPointSettings.tsx - /api/streamer/settings (POST)
- src/components/CardManager.tsx - /api/upload (POST), /api/cards (POST, PUT), /api/cards/${cardId} (DELETE)
- src/app/battle/page.tsx - /api/battle/start (POST)

**変更内容**:
- 各ファイルに `import { fetchWithCSRF } from '@/lib/client/csrf'` を追加
- POST/PUT/DELETEリクエストを `fetch()` から `fetchWithCSRF()` に置き換え
- GETリクエストと保護対象外のルートは変更なし
