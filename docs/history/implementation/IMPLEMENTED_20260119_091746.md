### 🔴 高優先度の修正（完了）

#### 1. トークン生成のレースコンディション対策

**問題点**: 複数のリクエストが同時に到着した場合、トークンが上書きされ、先に到着したリクエストが403エラーになる可能性がありました。

**修正内容**:
- `src/lib/csrf.ts` の `setCSRFToken()` 関数を idempotent に修正
- 既に CSRF トークンがセッションに存在する場合、新しいトークンを生成せずに既存のトークンを返すように変更
- 同時実行リクエストによるトークンの上書きを防止

```typescript
// src/lib/csrf.ts:17-35
export async function setCSRFToken(): Promise<string> {
  const cookieStore = await cookies()
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value

  if (!sessionCookie) {
    throw new Error('No session found')
  }

  const session = parseSession(sessionCookie)

  // 既にトークンが存在する場合は返す（idempotent）
  if (session.csrfToken) {
    return session.csrfToken
  }

  const token = generateCSRFToken()
  const userId = session.twitchUserId

  const updatedSession = {
    ...session,
    csrfToken: token,
  }

  cookieStore.set(COOKIE_NAMES.SESSION, JSON.stringify(updatedSession), {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 7 * 24 * 60 * 60,
  })

  logger.info(`CSRF token generated for user ${userId}`)
  return token
}
```

#### 2. エラーメッセージの統合

**問題点**: エラーメッセージが異なると、攻撃者がエラーメッセージから情報を得られる可能性がありました（例: "No session found" でセッションの有無が判明する）。

**修正内容**:
- `src/lib/csrf.ts` の `validateCSRFToken()` 関数のすべてのエラーメッセージを `ERROR_MESSAGES.CSRF_TOKEN_INVALID` に統一
- 攻撃者がエラーメッセージから情報を得られないようにする
- ログメッセージは詳細なまま維持（デバッグ用）

```typescript
// src/lib/csrf.ts:60-81
export async function validateCSRFToken(
  request: Request
): Promise<{ valid: boolean; error?: string }> {
  const cookieStore = await cookies()
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value

  if (!sessionCookie) {
    logger.warn('CSRF validation failed: No session found')
    return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
  }

  const session = parseSession(sessionCookie)
  const sessionToken = session.csrfToken

  if (!sessionToken) {
    logger.warn('CSRF validation failed: No CSRF token in session')
    return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
  }

  const requestToken = request.headers.get(CSRF_CONFIG.HEADER_NAME)

  if (!requestToken) {
    logger.warn('CSRF validation failed: CSRF token missing in request')
    return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
  }

  // ... 他の検証処理
}
```

#### 3. Sessionインターフェースの型安全性向上

**問題点**: `JSON.parse()` の戻り値が `any` 型になり、実行時に型エラーが発生する可能性がありました。

**修正内容**:
- `src/lib/session.ts` に `parseSession()` 関数を追加
- `Session` 型を使用したランタイム検証を追加
- `src/lib/csrf.ts` の `JSON.parse()` を `parseSession()` に置き換え

```typescript
// src/lib/session.ts:38-54
function parseSession(raw: string): Session {
  try {
    const parsed = JSON.parse(raw)

    if (!parsed.twitchUserId || !parsed.twitchUsername || !parsed.expiresAt) {
      throw new Error('Invalid session: missing required fields')
    }

    return parsed as Session
  } catch (error) {
    if (error instanceof Error) {
      throw new Error(`Invalid session format: ${error.message}`)
    }
    throw new Error('Invalid session format')
  }
}

export { parseSession }
```

```typescript
// src/lib/csrf.ts の変更
import { Session, parseSession } from './session'

// JSON.parse(sessionCookie) を parseSession(sessionCookie) に置き換え
const session = parseSession(sessionCookie)
```

### Phase 1: 基礎コンポーネントの実装

#### 1. src/lib/csrf.ts - CSRFトークン管理モジュール

CSRFトークンの生成、保存、検証を行うモジュールを実装しました。

**実装した関数**:
- `generateCSRFToken()` - 暗号学的に安全な乱数を使用して32バイトのトークンを生成
- `setCSRFToken()` - セッションにCSRFトークンを保存（idempotent）
- `validateCSRFToken(request)` - リクエストのCSRFトークンを検証（タイミング攻撃対策、Origin/Referer検証あり、エラーメッセージ統合済み）
- `getCSRFToken()` - 現在のセッションからCSRFトークンを取得
- `clearCSRFToken()` - セッションからCSRFトークンをクリア

**セキュリティ対策**:
- `crypto.randomBytes` による暗号学的に強力な乱数生成
- `crypto.timingSafeEqual` によるタイミング攻撃対策
- トークン長の事前検証によるタイミング攻撃防止
- Origin/Refererヘッダー検証による多層防御
- エラー時にloggerとSentryに記録
- エラーメッセージの統合による情報漏洩防止
