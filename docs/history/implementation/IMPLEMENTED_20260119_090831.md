## Issue #55: Critical Security - Missing CSRF Protection on State-Changing API Routes

### 概要
設計書 docs/ARCHITECTURE.md に基づいてCSRF保護を実装し、コードレビュー（docs/REVIEW.md）で指摘された問題点を修正しました。

## レビュー指摘事項への対応

### 🔴 高優先度の修正

#### 1. OAuth認証後にCSRFトークンを自動生成する仕組みの実装

**問題点**: Twitch OAuth認証後、ユーザーはセッションを持ちますがCSRFトークンは存在しません。初回POSTリクエスト時に403エラーが発生していました。

**修正内容**:
- `src/app/api/auth/twitch/callback/route.ts` に `setCSRFToken()` を呼び出す処理を追加
- OAuth認証成功後に自動的にCSRFトークンを生成してセッションに保存
- 認証直後のPOSTリクエストも正常に動作するよう修正

```typescript
// src/app/api/auth/twitch/callback/route.ts:146-150
// CSRFトークンを生成してセッションに保存
import { setCSRFToken } from '@/lib/csrf'

await setCSRFToken()

// Clear state cookie
cookieStore.delete('twitch_auth_state')
```

#### 2. ユニットテストを実際のコードを使用するよう修正

**問題点**: テストファイル内で`validateCSRFToken`、`setCSRFToken`等の関数を再実装しており、本番コードを変更してもテストが気づかない問題がありました。

**修正内容**:
- `tests/unit/csrf.test.ts` から関数の再実装を削除
- 実際の `@/lib/csrf.ts` から関数をインポートしてテスト
- モックオブジェクトの型定義を追加
- テストの信頼性を大幅に向上

```typescript
// 修正前: 関数を再実装
function generateCSRFToken(): string {
  return mockRandomBytes(CSRF_CONFIG.TOKEN_LENGTH).toString('hex')
}

// 修正後: 実際のコードを使用
import { generateCSRFToken, validateCSRFToken, setCSRFToken, getCSRFToken } from '@/lib/csrf'
```

#### 3. トークン長検証の追加

**問題点**: `Buffer.from()`は文字列長が異なる場合でも例外を投げず、`timingSafeEqual`で例外が発生する可能性があり、例外情報を攻撃者が利用してトークン長の情報を得られるリスクがありました。

**修正内容**:
- `src/lib/csrf.ts` の `validateCSRFToken` 関数にトークン長チェックを追加
- timingSafeEqualを呼び出す前にトークン長が一致していることを確認
- 長さが異なる場合は検証失敗として扱う

```typescript
// src/lib/csrf.ts:75-82
// トークン長の検証（タイミング攻撃対策）
if (sessionToken.length !== requestToken.length) {
  logger.warn('CSRF token length mismatch', {
    userId: session.twitchUserId,
    sessionTokenLength: sessionToken.length,
    requestTokenLength: requestToken.length,
  })
  return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
}
```

### 🟡 中優先度の修正

#### 4. Origin/Referer検証の追加

**問題点**: 多層防御としてOrigin/Referer検証が欠如していました。

**修正内容**:
- `src/lib/csrf.ts` の `validateCSRFToken` 関数にOrigin/Refererヘッダーの検証を追加
- Originヘッダーが存在する場合はアプリケーションドメインと照合
- Originがない場合はRefererヘッダーを確認
- 追加の防御レイヤーとして機能

```typescript
// src/lib/csrf.ts:84-116
// Origin/Referer検証（追加の防御レイヤー）
const origin = request.headers.get('origin')
const referer = request.headers.get('referer')
const appUrl = process.env.NEXT_PUBLIC_APP_URL

if (origin) {
  try {
    const originUrl = new URL(origin)
    const appUrlParsed = new URL(appUrl || 'http://localhost:3000')

    if (originUrl.origin !== appUrlParsed.origin) {
      logger.warn('CSRF origin validation failed', {
        userId: session.twitchUserId,
        origin,
        expectedOrigin: appUrlParsed.origin,
      })
      return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
    }
  } catch (error) {
    return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
  }
} else if (referer) {
  try {
    const refererUrl = new URL(referer)
    const appUrlParsed = new URL(appUrl || 'http://localhost:3000')

    if (!refererUrl.origin.startsWith(appUrlParsed.origin)) {
      logger.warn('CSRF referer validation failed', {
        userId: session.twitchUserId,
        referer,
        expectedOrigin: appUrlParsed.origin,
      })
      return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
    }
  } catch (error) {
    return { valid: false, error: ERROR_MESSAGES.CSRF_TOKEN_INVALID }
  }
}
```

#### 5. ログアウト時のCSRFトークン無効化

**問題点**: ログアウト時にCSRFトークンが無効化されず、セキュリティリスクがありました。

**修正内容**:
- `src/lib/csrf.ts` に `clearCSRFToken()` 関数を追加
- `src/app/api/auth/logout/route.ts` でログアウト時にCSRFトークンをクリア
- POSTおよびGET両方のログアウトハンドラーに対応

```typescript
// src/lib/csrf.ts:160-184
export async function clearCSRFToken(): Promise<void> {
  const cookieStore = await cookies()
  const sessionCookie = cookieStore.get(COOKIE_NAMES.SESSION)?.value

  if (!sessionCookie) {
    return
  }

  const session = JSON.parse(sessionCookie)
  const updatedSession = {
    ...session,
    csrfToken: undefined,
  }

  cookieStore.set(COOKIE_NAMES.SESSION, JSON.stringify(updatedSession), {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 7 * 24 * 60 * 60,
  })

  logger.info(`CSRF token cleared for user ${session.twitchUserId}`)
}
```

#### 6. Sessionインターフェースの更新

**修正内容**:
- `src/lib/session.ts` のSessionインターフェースに `csrfToken?: string` フィールドを追加
- TypeScriptでの適切な型定義


## 実装内容（修正前の内容は継続）

### Phase 1: 基礎コンポーネントの実装

#### 1. src/lib/csrf.ts - CSRFトークン管理モジュール（修正済み）

CSRFトークンの生成、保存、検証を行うモジュールを実装しました。

**実装した関数**:
- `generateCSRFToken()` - 暗号学的に安全な乱数を使用して32バイトのトークンを生成
- `setCSRFToken()` - セッションにCSRFトークンを保存
- `validateCSRFToken(request)` - リクエストのCSRFトークンを検証（タイミング攻撃対策、Origin/Referer検証あり）
- `getCSRFToken()` - 現在のセッションからCSRFトークンを取得
- `clearCSRFToken()` - セッションからCSRFトークンをクリア（新規追加）

**セキュリティ対策**:
- `crypto.randomBytes` による暗号学的に強力な乱数生成
- `crypto.timingSafeEqual` によるタイミング攻撃対策
- トークン長の事前検証によるタイミング攻撃防止
- Origin/Refererヘッダー検証による多層防御
- エラー時にloggerとSentryに記録

#### 2. src/app/api/csrf-token/route.ts - CSRFトークン取得API

認証済みユーザーがCSRFトークンを取得するためのAPIエンドポイントを実装しました。

**実装内容**:
- GETメソッドのみを許可
- 認証済みユーザーのみアクセス可能
- `setCSRFToken()` を呼び出してトークンを生成
- `{ csrfToken: token }` 形式で返却
