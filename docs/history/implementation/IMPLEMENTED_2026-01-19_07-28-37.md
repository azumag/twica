### レビューからの修正内容

#### 1. `src/lib/realtime.ts` の修正

**修正1: broadcastGachaResult関数のチャネルクリーンアップのロジックエラー**

レビューエージェントからの指摘:
1. 成功した場合、`channel.send()` の後に `client.removeChannel(channel)` を呼んでから `return` していますが、その後 `finally` ブロックでもう一度 `client.removeChannel(channel)` が呼ばれます
2. ループ内で毎回新しいチャネルを作成していますが、失敗した場合、古いチャネルがクリーンアップされる前に次のループが開始される可能性があります

修正内容:
- チャネルの作成をループの外に移動
- 成功した場合は `return` し、`finally` ブロックでのみチャネルをクリーンアップ
- ループ内でチャネルを作成しないように変更

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload,
  options: { maxRetries?: number; retryDelay?: number } = {}
): Promise<void> {
  const { maxRetries = 3, retryDelay = 1000 } = options
  const client = getSupabaseRealtimeClient()
  const channel = client.channel(`gacha:${streamerId}`)

  try {
    let attemptCount = 0
    while (attemptCount <= maxRetries) {
      try {
        await channel.send({
          type: 'broadcast',
          event: 'gacha_result',
          payload,
        })
        return
      } catch (error) {
        attemptCount++
        logger.warn(`Broadcast attempt ${attemptCount}/${maxRetries} failed:`, error)

        if (attemptCount > maxRetries) {
          logger.error(`Failed to broadcast gacha result for streamer ${streamerId} after ${maxRetries} attempts:`, error)
          reportRealtimeError(error, {
            action: 'broadcast',
            streamerId,
            retryCount: attemptCount - 1,
          })
          throw error
        }

        const delay = attemptCount * retryDelay
        logger.info(`Retrying broadcast in ${delay}ms...`)
        await new Promise(resolve => setTimeout(resolve, delay))
      }
    }
  } finally {
    try {
      client.removeChannel(channel)
    } catch (cleanupError) {
      logger.warn(`Failed to cleanup channel for streamer ${streamerId}:`, cleanupError)
    }
  }
}
```

**変更点:**
1. チャネルの作成をループの外に移動（`const client = getSupabaseRealtimeClient()` と `const channel = client.channel(...)` をループ外に）
2. 成功時に `return` し、`finally` ブロックでのみチャネルをクリーンアップ
3. 再試行ロジックを修正（`attemptCount` を使用）

**修正2: broadcastGachaResult関数の再接続ロジックの論理エラー**

レビューエージェントからの指摘:
`while (retryCount <= maxRetries)` の条件が間違っており、実際には4回試行されますが、`maxRetries = 3` は「最大再試行回数」を意味するため、合計で「初回 + 再試行3回 = 4回」試行されます。

修正内容:
- `retryCount` を `attemptCount` に変更
- 条件を `attemptCount > maxRetries` に変更
- 再試行回数を明確にする

#### 3. `src/app/overlay/[streamerId]/page.tsx` の修正

**修正4: 接続状態のタイムアウト処理の追加**

レビューエージェントからの指摘:
初期値が `'connecting'` に設定されていますが、実際の接続が開始されるのは `useEffect` 内の `subscribeToGachaResults` が呼ばれてからです。また、`onSuccess` コールバックで `'connected'` に設定されるため、初回接続が遅延した場合、ユーザーはずっと「接続中」を見続けることになります。

修正内容:
- タイムアウト処理を追加（10秒後に接続タイムアウトを表示）
- タイムアウト時にエラー状態に変更

```typescript
useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    if (payload.type === 'gacha' && payload.card) {
      displayResult({
        card: payload.card as unknown as Card,
        userTwitchUsername: payload.userTwitchUsername,
      });
    }
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });

  const timeoutId = setTimeout(() => {
    if (connectionStatus === 'connecting') {
      setConnectionStatus('error');
      setErrorMessage('Connection timeout');
    }
  }, 10000);

  cleanupRef.current = cleanup;

  return () => {
    clearTimeout(timeoutId);
    if (cleanupRef.current) {
      cleanupRef.current();
    }
    if (animationTimeoutRef.current) {
      clearTimeout(animationTimeoutRef.current);
    }
  };
}, [streamerId, displayResult]);
```

**変更点:**
1. タイムアウト処理を追加（10秒）
2. タイムアウト時にエラー状態に変更
3. クリーンアップ時にタイムアウトをキャンセル
