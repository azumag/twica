## Critical Issuesの修正

### CSRF-01: トークンハッシュにソルトが使用されていない

**問題:** ハッシュ関数にソルトが使用されていないため、トークンが漏洩した場合、レインボーテーブル攻撃で元のパスワード（トークン）を逆算される可能性がある。

**場所:** src/lib/csrf.ts:33-36

**修正前:**
```typescript
export function hashToken(token: string): string {
  return createHash('sha256').update(token).digest('hex')
}
```

**修正後:**
```typescript
export function hashToken(token: string): string {
  const salt = process.env.CSRF_TOKEN_SALT || 'default-salt'
  return createHash('sha256').update(token + salt).digest('hex')
}
```

**効果:**
- ソルトによりレインボーテーブル攻撃を防止
- 環境変数によるソルトのカスタマイズが可能
- デフォルトソルトのフォールバックを実装

---

### CSRF-02: JSON.parse/JSON.stringifyの過剰使用によるパフォーマンス低下

**問題:** `JSON.parse(sessionCookie)` と `JSON.stringify()` を連続で使用するのは非効率であり、3回のパース/ストリング化が追加されている。

**場所:** src/lib/csrf.ts:103

**修正前:**
```typescript
const updatedSession = parseSession(JSON.stringify({
  ...JSON.parse(sessionCookie),
  csrfTokenHash: tokenHash,
  version: session.version + 1,
}))
```

**修正後:**
```typescript
const updatedSession = { ...session, csrfTokenHash: tokenHash, version: session.version + 1 }
```

**効果:**
- 不要な `JSON.parse` と `JSON.stringify` の使用を削除
- オブジェクトスプレッド構文を使用して単純化
- セッション更新時のCPU使用率を削減

---

### CSRF-03: キャッシュ戦略の不適切な適用

**問題:** Reactの`cache`はReactコンポーネント内またはReact Server Component内でのみ動作し、API RouteやServer Actionでは異なるライフサイクルを持つため使用すべきではない。

**場所:** src/lib/csrf.ts 全体

**確認結果:**
- 現在のコードには `cache` 関数の使用は見つからなかった
- 削除不要

**注意:**
- 以前の実装（docs/IMPLEMENTED.mdの履歴）には `cache` 関数の使用が記載されていたが、既に削除されていた可能性がある
- 今回の修正で新たに `cache` 関数を使用する実装は追加しない
