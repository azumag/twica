## 詳細レビュー

### 1. CSRFトークンモジュール (src/lib/csrf.ts)

**評価: 要改善**

#### ポジティブな点:
- `crypto.randomBytes`による暗号学的に安全な乱数生成 ✓
- `crypto.timingSafeEqual`によるタイミング攻撃対策 ✓
- Sentryへのエラー報告 ✓

#### 問題点:

1. **重大なバグ: タイミング攻撃の例外処理不足** (`src/lib/csrf.ts:76-79`)
   ```typescript
   const isValid = timingSafeEqual(
     Buffer.from(sessionToken),
     Buffer.from(requestToken)
   )
   ```
   `Buffer.from()`は文字列長が異なる場合でも例外を投げず、長さが異なる場合は`timingSafeEqual`で例外が発生します。この例外情報を攻撃者が利用してトークン長の情報を得られる可能性があります。

2. **SameSite='lax'の継続使用**
   設計書でも指摘されているように、`sameSite: 'lax'`はCSRFリスクを完全には排除できません。認証後の最初のリクエストでは保護が弱くなります。

3. **トークンのローテーション機能がない**
   セッション有効期間（7日間）中、トークンは固定されたままです。長時間有効なトークンはリスクを高めます。

### 4. クライアント側CSRFユーティリティ (src/lib/client/csrf.ts)

**評価: 要改善**

#### 問題点:

1. **XSS脆弱性のリスク** (localStorage使用)
   ```typescript
   localStorage.setItem('csrfToken', csrfToken)
   ```
   XSS脆弱性がある場合、攻撃者がlocalStorageからCSRFトークンを窃取できます。HttpOnly cookieの方が安全です。

2. **トークン取得エラー時の処理**
   ```typescript
   if (!response.ok) {
     throw new Error('Failed to fetch CSRF token')
   }
   ```
   エラー発生時にUnhandled rejectionとなります。

---

### 5. ユニットテスト (tests/unit/csrf.test.ts)

**評価: 不可**

#### 重大な問題点:

1. **テストでの二重実装**
   テストファイル内で`validateCSRFToken`、`setCSRFToken`、その他の関数を**再定義**しています:
   ```typescript
   // 直接関数をテスト用に実装
   function generateCSRFToken(): string {
     return mockRandomBytes(CSRF_CONFIG.TOKEN_LENGTH).toString('hex')
   }

   async function validateCSRFToken(request: Request): Promise<{ valid: boolean; error?: string }> {
     // ...完全な再実装
   }
   ```

   これは**深刻な問題**です:
   - 本番コードを変更してもテストが気づかない
   - テストしている内容が実際のコードと異なる可能性がある
   - DRY原則に違反

2. **モックの不一致**
   `crypto`モジュールをモックしていますが、テスト内で直接`timingSafeEqual`を使用しています。

## 結論

**レビュー不合格**

実装は基本的なCSRF Protectionを提供しますが、以下の重大な問題が解決されるまでマージ不建议です:

1. **ユニットテストでの関数再実装** - テストの価値が大きく損なわれる
2. **OAuthフローとの競合** - 認証後に403エラーが発生
3. **トークン長の検証不足** - タイミング攻撃の脆弱性
4. **Origin/Referer検証の欠如** - 多層防御がない
5. **ログアウト時のトークン無効化** - セキュリティリスク

**修正優先順位:**

🔴 **高優先度:**
- OAuth認証後にCSRFトークンを自動生成する仕組みの実装
- ユニットテストを実際のコードを使用するよう修正
- トークン長検証の追加

🟡 **中優先度:**
- Origin/Referer検証の追加
- ログアウト時のCSRFトークン無効化
- localStorageのHttpOnly cookieへの変更検討

🟢 **低優先度:**
- 統合テストの追加
- トークンローテーション機能
