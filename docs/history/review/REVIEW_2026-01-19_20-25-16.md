## 重大な問題 (Critical)

### CSRF-01: トークンハッシュにソされていない

**場所ルトが使用:** ARCHITECTURE.md:227-229

```typescript
function hashToken(token: string): string {
  return crypto.createHash('sha256').update(token).digest('hex')
}
```

**問題:** ハッシュ関数にソルトが使用されていないため、トークンが漏洩した場合、レインボーテーブル攻撃で元のパスワード（トークン）を逆算される可能性がある。

**影響:** トークン漏洩時の二次被害リスク

**修正案:**
```typescript
function hashToken(token: string): string {
  const salt = process.env.CSRF_TOKEN_SALT || 'default-salt'
  return crypto.createHash('sha256').update(token + salt).digest('hex')
}
```

### CSRF-02: JSON.parse/JSON.stringifyの過剰使用によるパフォーマンス低下

**場所:** IMPLEMENTED.md:21-26, 51-55, 91-94

```typescript
const updatedSession = parseSession(JSON.stringify({
  ...JSON.parse(sessionCookie),
  csrfTokenHash: tokenHash,
  version: session.version + 1,
}))
```

**問題:**
1. `JSON.parse(sessionCookie)` と `JSON.stringify()` を連続で使用するのは非効率
2. 3回のパース/ストリング化が追加される
3. `structuredClone` または `Object.assign` で単純に解決可能

**影響:** セッション更新時のCPU使用率増加

**修正案:**
```typescript
const updatedSession = { ...session, csrfTokenHash: tokenHash, version: session.version + 1 }
```

---

### CSRF-03: キャッシュ戦略の不適切な適用

**場所:** IMPLEMENTED.md:68-71

```typescript
const session = cache(() => parseSession(sessionCookie))()
```

**問題:**
1. Reactの`cache`はReactコンポーネント内またはReact Server Component内でのみ動作する
2. API RouteやServer Actionでは異なるライフサイクルを持つ
3. 各リクエストで異なるcookie值を持つ可能性があるため、リクエスト間でキャッシュを共有するとバグの原因となる

**影響:** 不正なセッション情報の使用、認証バイパス

## 低優先度の問題 (Low)

### SIMP-01: 過度に複雑なidempotent設計

**場所:** ARCHITECTURE.md:245-252

```typescript
if (session.csrfTokenHash) {
  const existingToken = getCSRFTokenFromCookie(cookieStore)
  if (existingToken) {
    return existingToken
  }
}
```

**問題:** cookieとセッションの両方をチェックするidempotent設計は複雑性を増加させる。単純な「常に新しいトークンを生成」アプローチの方が安全でシンプル

---

### SIMP-02: レビューAgentによる修正の妥当性

**場所:** IMPLEMENTED.md:23-25

```typescript
...JSON.parse(sessionCookie),
```

**問題:** `session`変数が既に存在するのに、なぜか`sessionCookie`を再度パースしている。冗長なコード
