## Critical Issues（修正必須）

### 1. broadcastGachaResult関数のエラーハンドリング不足

**ファイル**: `src/lib/realtime.ts:52-73`

**問題点**:
設計書の機能要件には「Realtime接続のエラーハンドリング」と「再接続ロジックを実装」が含まれていますが、`broadcastGachaResult`関数には再接続ロジックがなく、エラーが発生した場合に単純にthrowしているだけです。

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload
): Promise<void> {
  const client = getSupabaseRealtimeClient()
  const channel = client.channel(`gacha:${streamerId}`)

  try {
    await channel.send({
      type: 'broadcast',
      event: 'gacha_result',
      payload,
    })
  } catch (error) {
    logger.error(`Failed to broadcast gacha result for streamer ${streamerId}:`, error)
    reportRealtimeError(error, {
      action: 'broadcast',
      streamerId,
    })
    throw error  // ⚠️ 再接続ロジックがない
  }
}
```

**影響**:
- 一時的なネットワークエラーで配信が失敗する可能性がある
- ユーザー体験が悪化する

**修正案**:
再接続ロジックを追加する：

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload,
  options: { maxRetries?: number; retryDelay?: number } = {}
): Promise<void> {
  const { maxRetries = 3, retryDelay = 1000 } = options
  let retryCount = 0

  while (retryCount <= maxRetries) {
    try {
      const client = getSupabaseRealtimeClient()
      const channel = client.channel(`gacha:${streamerId}`)

      await channel.send({
        type: 'broadcast',
        event: 'gacha_result',
        payload,
      })
      return
    } catch (error) {
      retryCount++
      logger.warn(`Broadcast attempt ${retryCount}/${maxRetries} failed:`, error)

      if (retryCount <= maxRetries) {
        const delay = retryCount * retryDelay
        logger.info(`Retrying broadcast in ${delay}ms...`)
        await new Promise(resolve => setTimeout(resolve, delay))
      } else {
        logger.error(`Failed to broadcast gacha result for streamer ${streamerId} after ${maxRetries} attempts:`, error)
        reportRealtimeError(error, {
          action: 'broadcast',
          streamerId,
          retryCount,
        })
        throw error
      }
    }
  }
}
```

### 2. broadcastGachaResult関数のchannelクリーンアップが不足

**ファイル**: `src/lib/realtime.ts:52-73`

**問題点**:
`broadcastGachaResult`関数は呼び出されるたびに新しいchannelを作成していますが、channelをクリーンアップしていません。これは、Supabase Realtimeの制約により、同じstreamerIdに対して複数のchannelを作成すると、古いchannelが自動的に削除されますが、確実なクリーンアップが必要です。

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload
): Promise<void> {
  const client = getSupabaseRealtimeClient()
  const channel = client.channel(`gacha:${streamerId}`)  // ⚠️ 新しいchannelを作成

  try {
    await channel.send({
      type: 'broadcast',
      event: 'gacha_result',
      payload,
    })
    // ⚠️ channelをクリーンアップしていない
  } catch (error) {
    // ...
  }
}
```

**影響**:
- メモリリークの可能性がある
- 同じstreamerIdに対して複数のchannelが作成される可能性がある

**修正案**:
channelをクリーンアップする：

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload
): Promise<void> {
  const client = getSupabaseRealtimeClient()
  const channel = client.channel(`gacha:${streamerId}`)

  try {
    await channel.send({
      type: 'broadcast',
      event: 'gacha_result',
      payload,
    })
  } catch (error) {
    logger.error(`Failed to broadcast gacha result for streamer ${streamerId}:`, error)
    reportRealtimeError(error, {
      action: 'broadcast',
      streamerId,
    })
    throw error
  } finally {
    client.removeChannel(channel)  // channelをクリーンアップ
  }
}
```

### 3. 接続状態の初期値が矛盾している

**ファイル**: `src/app/overlay/[streamerId]/page.tsx:52, 97-99`

**問題点**:
初期値が `'connecting'` に設定されていますが、実際の接続が開始されるのはuseEffect内の `subscribeToGachaResults` が呼ばれてからです。また、`onSuccess` コールバックで `'connected'` に設定されるため、初回接続が遅延した場合、ユーザーはずっと「接続中」を見続けることになります。

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('connecting');

useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');  // ⚠️ 成功時のみ更新
    },
  });
  // ⚠️ 接続開始時に 'connecting' 状態が更新されていない
}, [streamerId, displayResult]);
```

**影響**:
- 初期状態が正しく表示されない
- 初回接続が遅延した場合、ユーザーが「接続中」を見続ける可能性がある

**修正案**:
初期値を `'disconnected'` に設定し、接続開始時に `'connecting'` に更新する：

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('disconnected');

useEffect(() => {
  setConnectionStatus('connecting');  // 接続開始時に設定

  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });

  return cleanup;
}, [streamerId, displayResult]);
```

ただし、ESLintのルール `react-hooks/set-state-in-effect` に違反する可能性があるため、以下のいずれかの方法を推奨します：

**修正案2**:
初期値を `'connecting'` のままにし、接続確立時にのみ状態を更新する：

```typescript
// 初期値を 'connecting' のままにする
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('connecting');

// 接続開始時にタイムアウトを設定
useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });

  // 10秒間接続できない場合はエラー状態にする
  const timeoutId = setTimeout(() => {
    if (connectionStatus === 'connecting') {
      setConnectionStatus('error');
      setErrorMessage('Connection timeout');
    }
  }, 10000);

  return () => {
    clearTimeout(timeoutId);
    cleanup();
  };
}, [streamerId, displayResult]);
```

// src/hooks/useRealtimeSubscription.ts
export function useRealtimeSubscription(
  streamerId: string,
  onMessage: (payload: GachaBroadcastPayload) => void
) {
  const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('disconnected')
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  useEffect(() => {
    const cleanup = subscribeToGachaResults(streamerId, onMessage, {
      maxRetries: 5,
      retryDelay: 3000,
      onError: (error) => {
        setConnectionStatus('error')
        setErrorMessage(error.message)
      },
      onSuccess: () => {
        setConnectionStatus('connected')
      },
    })

    return cleanup
  }, [streamerId, onMessage])

  return { connectionStatus, errorMessage }
}
