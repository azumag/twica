## 重大な問題点 (Critical Issues)

### 1. 設計書と実装の不一致（最も重大）

**ファイル**: `src/lib/csrf.ts:110行目`

**問題点**:
- ARCHITECTURE.mdでは「Double Submit Cookie Pattern with Hash Comparison」を採用すると記述
  - 非httpOnly cookieにトークンを保存（JavaScriptからアクセス可能）
  - クライアントはcookieからトークンを読み取り、X-CSRF-Tokenヘッダーに設定
  - サーバーはヘッダーの値のハッシュとセッションのハッシュを比較
- 実装（110行目）では `httpOnly: true` と設定されている
  - HttpOnly Cookieパターンが採用されている
  - X-CSRF-Tokenヘッダーは使用されていない
  - Cookieから直接トークンを取得して比較（158行目）

**影響**:
- セキュリティアーキテクチャの矛盾
- ドキュメントとコードの不一致による開発者への混乱
- 意図しないセキュリティ挙動の可能性

**修正方針**:
- HttpOnly Cookieパターンを採用する場合：ARCHITECTURE.mdを更新して実装に合わせる
- Double Submit Cookie Patternを採用する場合：実装を修正してhttpOnly: falseにする

**優先度**: 🔴 Critical - 即時修正必要

---

### 2. ARCHITECTURE.mdとIMPLEMENTED.mdの矛盾

**ファイル**: `docs/ARCHITECTURE.md`, `docs/IMPLEMENTED.md`

**問題点**:
- ARCHITECTURE.mdは「Double Submit Cookie Pattern with Hash Comparison」を採用
- IMPLEMENTED.md（310-325行目）では「HttpOnly Cookieパターン」に移行したと記述
- 設計書が更新されていない

**影響**:
- 開発者間の認識の不一致
- 将来の機能追加時の混乱
- コードレビュー時の判断基準の不明確化

**修正方針**:
- 採用するパターンを決定し、ARCHITECTURE.mdを更新する
- IMPLEMENTED.mdとの整合性を確保する

**優先度**: 🔴 Critical - 即時修正必要

**修正方針**:

**優先度**: 🟡 Medium

## 中程度の問題点 (Medium Issues)

### 4. clearCSRFToken()でバージョン番号を更新していない

**ファイル**: `src/lib/csrf.ts:216-244行目`

**問題点**:
```typescript
// セッションからハッシュを削除
if (session.csrfTokenHash) {
  const sessionWithoutCsrf = { ...session }
  delete sessionWithoutCsrf.csrfTokenHash

  cookieStore.set(COOKIE_NAMES.SESSION, JSON.stringify(sessionWithoutCsrf), {
    // ...
  })
}
```
- セッションからcsrfTokenHashを削除しているが、versionフィールドを更新していない
- 楽観的ロックの一貫性が壊れる可能性がある

**影響**:
- 同時実行時のデータ整合性の問題
- 予期せぬトークン検証エラーの可能性

**修正方針**:
- セッション更新時にversionフィールドをインクリメントする
- 楽観的ロックを実装して一貫性を確保する

**優先度**: 🟡 Medium

## Potential Bugs & Edge Cases

### ⚠️ 注意が必要

1. **セッション更新の競合条件**
   - clearCSRFToken()でバージョン番号を更新していない
   - 楽観的ロックの一貫性が壊れる可能性
