## 発見された問題

### 🔴 重大 (Critical) - 1件

#### 1. トークン期限切れチェックのバグ

**ファイル**: `src/lib/twitch/token-manager.ts:41`

**問題コード**:
```typescript
const expiresAt = new Date(user.twitch_token_expires_at);

if (expiresAt > now) {
  return user.twitch_access_token;
}
```

**問題点**:
- `user.twitch_token_expires_at` が null、undefined、または不正な形式の場合、`new Date()` は "Invalid Date" を生成する
- JavaScriptでは "Invalid Date" > Date() は常に false を返すため、論理的にはトークン期限切れとして処理される
- しかし、この動作は信頼性がなく、予測できない結果を招く可能性がある

**推奨修正**:
```typescript
if (!user.twitch_token_expires_at) {
  throw new TwitchTokenError(
    'Token expiry date is missing',
    'NO_TOKEN'
  );
}

const expiresAt = new Date(user.twitch_token_expires_at);
if (isNaN(expiresAt.getTime())) {
  throw new TwitchTokenError(
    'Invalid token expiry date format',
    'NO_TOKEN'
  );
}

const now = new Date();
if (expiresAt > now) {
  return user.twitch_access_token;
}
```

### 🟡 中程度 (Medium) - 3件

#### 2. エラーハンドリングのコード重複

**ファイル**: `src/app/api/twitch/rewards/route.ts:17-44`

**問題点**:
- `NO_TOKEN`、`REFRESH_FAILED`、`DATABASE_ERROR` のエラー処理ロジックが重複している
- `reportError` の呼び出しパターンが同一で、将来的な保守が困難

**推奨修正**:
```typescript
function handleTwitchTokenError(error: TwitchTokenError, twitchUserId: string): never {
  const errorMessages: Record<TwitchTokenError['code'], string> = {
    'NO_TOKEN': 'Twitch連携が必要です。再ログインしてください。',
    'REFRESH_FAILED': 'Twitchトークンの更新に失敗しました。再ログインしてください。',
    'DATABASE_ERROR': 'サーバーエラーが発生しました。',
  };

  reportError(error, {
    context: 'getTwitchAccessToken',
    code: error.code,
    userId: twitchUserId
  });

  throw new Error(errorMessages[error.code] || 'サーバーエラーが発生しました。');
}
```

#### 3. エラーメッセージの定数化不足

**ファイル**: `src/app/api/twitch/rewards/route.ts`

**問題点**:
- ユーザーフレンドリーなエラーメッセージがハードコードされている
- 他のAPIルートでも同様のメッセージが必要になる可能性があり、国際化対応を困難にする

**推奨修正**:
`src/lib/constants.ts` に以下の定数を追加:
```typescript
export const ERROR_MESSAGES = {
  // ... 既存のエラー ...
  TWITCH_TOKEN_REQUIRED: 'Twitch連携が必要です。再ログインしてください。',
  TWITCH_TOKEN_REFRESH_FAILED: 'Twitchトークンの更新に失敗しました。再ログインしてください。',
} as const;
```

#### 4. エラー発生時のスタックトレース欠落

**ファイル**: `src/app/api/twitch/rewards/route.ts`

**問題点**:
- `getTwitchAccessTokenOrError` 関数内で新しい Error オブジェクトをスローする際に、元のスタックトレースが失われる
- Sentryでのデバッグが困難になる

**推奨修正**:
```typescript
const errorMessage = /* ... */;
const wrappedError = new Error(errorMessage);
wrappedError.stack = error.stack; // 元のエラーのスタックトレースを保持
throw wrappedError;
```
