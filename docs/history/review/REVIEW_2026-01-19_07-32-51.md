## Critical Issues（修正必須）

### 1. broadcastGachaResult関数のチャネルクリーンアップのロジックエラー

**ファイル**: `src/lib/realtime.ts:52-97`

**問題点**:
1. 成功した場合、`channel.send()` の後に `client.removeChannel(channel)` を呼んでから `return` していますが、この時点でまだブロードキャストが完了していない可能性があります
2. 成功時に `client.removeChannel(channel)` を呼んでから `return` していますが、その後 `finally` ブロックでもう一度 `client.removeChannel(channel)` が呼ばれます（行91）
3. ループ内で毎回新しいチャネルを作成していますが、失敗した場合、古いチャネルがクリーンアップされる前に次のループが開始される可能性があります

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload,
  options: { maxRetries?: number; retryDelay?: number } = {}
): Promise<void> {
  const { maxRetries = 3, retryDelay = 1000 } = options
  let retryCount = 0

  while (retryCount <= maxRetries) {
    const client = getSupabaseRealtimeClient()
    const channel = client.channel(`gacha:${streamerId}`)

    try {
      await channel.send({
        type: 'broadcast',
        event: 'gacha_result',
        payload,
      })
      client.removeChannel(channel)  // ⚠️ 送信直後にチャネルを削除
      return
    } catch (error) {
      retryCount++
      logger.warn(`Broadcast attempt ${retryCount}/${maxRetries} failed:`, error)

      if (retryCount <= maxRetries) {
        const delay = retryCount * retryDelay
        logger.info(`Retrying broadcast in ${delay}ms...`)
        await new Promise(resolve => setTimeout(resolve, delay))
      } else {
        logger.error(`Failed to broadcast gacha result for streamer ${streamerId} after ${maxRetries} attempts:`, error)
        reportRealtimeError(error, {
          action: 'broadcast',
          streamerId,
          retryCount,
        })
        throw error
      }
    } finally {
      try {
        client.removeChannel(channel)  // ⚠️ 成功時に2回削除される
      } catch (cleanupError) {
        logger.warn(`Failed to cleanup channel for streamer ${streamerId}:`, cleanupError)
      }
    }
  }
}
```

**影響**:
- チャネルが削除される前にブロードキャストが失敗する可能性がある
- 成功時に同じチャネルを2回削除しようとする
- メモリリークの可能性がある

**修正案**:
チャネルの作成をループの外に移動し、成功した場合は削除しないようにします：

```typescript
export async function broadcastGachaResult(
  streamerId: string,
  payload: GachaBroadcastPayload,
  options: { maxRetries?: number; retryDelay?: number } = {}
): Promise<void> {
  const { maxRetries = 3, retryDelay = 1000 } = options
  let retryCount = 0
  const client = getSupabaseRealtimeClient()
  const channel = client.channel(`gacha:${streamerId}`)

  try {
    while (retryCount <= maxRetries) {
      try {
        await channel.send({
          type: 'broadcast',
          event: 'gacha_result',
          payload,
        })
        return
      } catch (error) {
        retryCount++
        logger.warn(`Broadcast attempt ${retryCount}/${maxRetries} failed:`, error)

        if (retryCount <= maxRetries) {
          const delay = retryCount * retryDelay
          logger.info(`Retrying broadcast in ${delay}ms...`)
          await new Promise(resolve => setTimeout(resolve, delay))
        } else {
          logger.error(`Failed to broadcast gacha result for streamer ${streamerId} after ${maxRetries} attempts:`, error)
          reportRealtimeError(error, {
            action: 'broadcast',
            streamerId,
            retryCount,
          })
          throw error
        }
      }
    }
  } finally {
    client.removeChannel(channel)
  }
}
```

### 2. broadcastGachaResult関数の再接続ロジックの論理エラー

**ファイル**: `src/lib/realtime.ts:52-97`

**問題点**:
`while (retryCount <= maxRetries)` の条件が間違っています。`retryCount` は `0` から始まり、失敗した時にインクリメントされます。つまり：
- 初回実行: `retryCount = 0` (ループ開始)
- 1回目失敗: `retryCount = 1`
- 2回目失敗: `retryCount = 2`
- 3回目失敗: `retryCount = 3`
- 4回目失敗: `retryCount = 4` (ループ終了)

つまり、実際には4回試行されますが、`maxRetries = 3` は「最大再試行回数」を意味するため、合計で「初回 + 再試行3回 = 4回」試行されます。これは意図した挙動ではない可能性があります。

**影響**:
- 意図した回数よりも多くの再試行が行われる可能性がある

**修正案**:
条件を `retryCount < maxRetries` に変更するか、ロジックを見直します：

```typescript
// 修正案1: 条件を変更
while (retryCount < maxRetries) {
  // ...
}

// 修正案2: 再試行回数を明確にする
let attemptCount = 0
while (attemptCount <= maxRetries) {
  try {
    await channel.send({ ... })
    return
  } catch (error) {
    attemptCount++
    if (attemptCount > maxRetries) {
      throw error
    }
    // ...
  }
}
```

## Major Issues（修正推奨）

### 4. 接続状態の初期値が矛盾している

**ファイル**: `src/app/overlay/[streamerId]/page.tsx:52, 84-112`

**問題点**:
前回のレビューと同じ問題が残っています。初期値が `'connecting'` に設定されていますが、実際の接続が開始されるのは `useEffect` 内の `subscribeToGachaResults` が呼ばれてからです。また、`onSuccess` コールバックで `'connected'` に設定されるため、初回接続が遅延した場合、ユーザーはずっと「接続中」を見続けることになります。

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('connecting');

useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');  // 成功時のみ更新
    },
  });
  // ⚠️ 接続開始時に 'connecting' 状態が更新されていない
}, [streamerId, displayResult]);
```

**影響**:
- 初期状態が正しく表示されない
- 初回接続が遅延した場合、ユーザーが「接続中」を見続ける可能性がある

**修正案**:
初期値を `'disconnected'` に設定し、接続開始時に `'connecting'` に更新する：

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('disconnected');

useEffect(() => {
  setConnectionStatus('connecting');

  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });

  return cleanup;
}, [streamerId, displayResult]);
```

ただし、ESLintのルール `react-hooks/exhaustive-deps` に違反する可能性があるため、以下のいずれかの方法を推奨します：

**修正案2**:
初期値を `'connecting'` のままにし、接続確立時にのみ状態を更新する：

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('connecting');

useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });

  const timeoutId = setTimeout(() => {
    if (connectionStatus === 'connecting') {
      setConnectionStatus('error');
      setErrorMessage('Connection timeout');
    }
  }, 10000);

  return () => {
    clearTimeout(timeoutId);
    cleanup();
  };
}, [streamerId, displayResult]);
```
