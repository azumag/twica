## Critical Issues（修正必須）

### 1. 再接続ロジックのタイマー管理バグ

**ファイル**: `src/lib/realtime.ts:98, 157, 180`

**問題点**:
新しい再接続を開始する前に、既存の `retryTimeout` がクリアされず、複数の再接続タイマーが同時に存在する可能性があります。

```typescript
// Line 98
let retryTimeout: NodeJS.Timeout | null = null

// Line 100-109: cleanup関数でクリア
const cleanup = () => {
  if (retryTimeout) {
    clearTimeout(retryTimeout)
    retryTimeout = null
  }
  // ...
}

// Line 157, 180: 再接続時にタイマー設定（クリアしていない！）
if (retryCount < maxRetries) {
  retryCount++
  logger.info(`Retrying connection (attempt ${retryCount}/${maxRetries})...`)
  retryTimeout = setTimeout(subscribe, retryDelay)  // ⚠️ 前のタイマーがクリアされていない
}
```

**影響**:
- エラーが連続的に発生した場合、複数の再接続が同時に進行する
- サーバーに余分な負荷がかかる
- メモリリークの可能性

**修正案**:
`subscribe` 関数の冒頭でタイマーをクリアする、または再接続時に既存のタイマーをクリアする：

```typescript
const subscribe = () => {
  // 既存のタイマーをクリア
  if (retryTimeout) {
    clearTimeout(retryTimeout)
    retryTimeout = null
  }

  try {
    client = getSupabaseRealtimeClient()
    // ...
  }
}
```

### 2. 未対応のWebSocket接続ステータス

**ファイル**: `src/lib/realtime.ts:134`

**問題点**:
接続ステータスのチェックが `SUBSCRIBED`, `CLOSED`, `CHANNEL_ERROR` のみであり、`TIMED_OUT`, `SOCKET_CLOSED`, `JOIN_ERROR` などの重要なステータスが無視されています。

```typescript
.subscribe((status, err) => {
  if (status === 'SUBSCRIBED') {
    // ...
  } else if (status === 'CLOSED' || status === 'CHANNEL_ERROR') {
    // ⚠️ TIMED_OUT, SOCKET_CLOSED などが未対応
  }
})
```

**影響**:
- タイムアウトやソケットクローズ時に適切な再接続が行われない
- ユーザーが接続できない状態に陥る可能性がある

**修正案**:
デフォルトケースを追加し、未対応のステータスも再接続対象にする：

```typescript
.subscribe((status, err) => {
  if (status === 'SUBSCRIBED') {
    // ...
  } else {
    // SUBSCRIBED以外はすべてエラーとして扱う
    logger.warn(`Connection issue for gacha:${streamerId}, status: ${status}`)
    isSubscribed = false

    const error: RealtimeError = {
      type: 'connection',
      message: `Realtime connection issue: ${status}`,
      error: err,
    }

    logger.error(`Realtime error for streamer ${streamerId}:`, error)
    reportRealtimeError(err, {
      action: 'subscribe',
      streamerId,
      status,
      retryCount,
    })

    onError?.(error)

    if (retryCount < maxRetries) {
      retryCount++
      logger.info(`Retrying connection (attempt ${retryCount}/${maxRetries})...`)
      retryTimeout = setTimeout(subscribe, retryDelay)
    } else {
      logger.error(`Max retries (${maxRetries}) reached for gacha:${streamerId}`)
    }
  }
})
```

### 3. TypeScriptの型定義のプラットフォーム依存

**ファイル**: `src/lib/realtime.ts:98`, `src/app/overlay/[streamerId]/page.tsx:54`

**問題点**:
`NodeJS.Timeout` 型を使用しているが、この型はNode.js環境に特化しており、ブラウザ環境では正しく動作しない可能性があります。

```typescript
let retryTimeout: NodeJS.Timeout | null = null  // ⚠️ ブラウザでは未定義の可能性
```

**影響**:
- ブラウザ環境で型エラーが発生する可能性がある
- クロスプラットフォーム対応が不十分

**修正案**:
`number` 型を使用するか、型定義を修正する：

```typescript
let retryTimeout: number | null = null

// クリア時
if (retryTimeout !== null) {
  clearTimeout(retryTimeout)
  retryTimeout = null
}

// 設定時
retryTimeout = window.setTimeout(subscribe, retryDelay)
```

または、環境固有の型定義を条件分岐で使用する：

```typescript
let retryTimeout: ReturnType<typeof setTimeout> | null = null
```

## Major Issues（修正推奨）

### 4. 接続状態が初期化されない

**ファイル**: `src/app/overlay/[streamerId]/page.tsx:52, 97-99`

**問題点**:
初期状態が `'connecting'` に設定されていますが、接続開始時に状態が更新されません。接続成功時のみ `'connected'` に更新されるため、初回接続が遅延した場合に `'connecting'` 状態が永久に続く可能性があります。

```typescript
const [connectionStatus, setConnectionStatus] = useState<'connecting' | 'connected' | 'disconnected' | 'error'>('connecting');

useEffect(() => {
  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');  // ⚠️ 成功時のみ更新
    },
  });
  // ⚠️ 接続開始時に 'connecting' 状態が更新されていない
}, [streamerId, displayResult]);
```

**影響**:
- ユーザーが接続中であることが正しく表示されない
- 初回接続が失敗した場合、エラー表示が遅延する

**修正案**:
接続開始時に状態を更新する：

```typescript
useEffect(() => {
  setConnectionStatus('connecting');  // 接続開始時に設定

  const cleanup = subscribeToGachaResults(streamerId, (payload) => {
    // ...
  }, {
    onError: (error) => {
      setConnectionStatus('error');
      setErrorMessage(error.message);
    },
    onSuccess: () => {
      setConnectionStatus('connected');
    },
  });
}, [streamerId, displayResult]);
```

### 5. 再接続戦略が非効率（固定遅延）

**ファイル**: `src/lib/realtime.ts:88, 157, 180`

**問題点**:
再接続の遅延時間が固定（3秒）であり、指数バックオフやジッターを使用していません。これはサーバーへの負荷増加や再接続の失敗につながる可能性があります。

```typescript
const {
  maxRetries = 5,
  retryDelay = 3000,  // ⚠️ 固定遅延
  onError,
  onSuccess,
} = options
```

**影響**:
- 連続した再接続試行がサーバーに負荷をかける
- ネットワーク混雑時に再接続が競合して失敗する可能性がある

**修正案**:
指数バックオフとジッターを導入する：

```typescript
const getRetryDelay = (retryCount: number, baseDelay: number): number => {
  const backoffDelay = Math.min(baseDelay * Math.pow(2, retryCount), 30000); // 最大30秒
  const jitter = Math.random() * 1000; // 最大1秒のジッター
  return backoffDelay + jitter;
};

// 使用時
retryTimeout = setTimeout(subscribe, getRetryDelay(retryCount, retryDelay));
```

## Minor Issues（改善推奨）

### 6. CSPのセキュリティリスク

**ファイル**: `src/lib/constants.ts:190`

**問題点**:
本番環境で `'unsafe-inline'` を追加しており、XSS攻撃のリスクが増加しています。

```typescript
CSP_PRODUCTION: "... script-src 'self' 'unsafe-inline'; ..."
```

**推奨**:
将来の改善として、nonce-based CSP または hash-based CSP を導入することを検討してください。

### 7. 最大再接続回数到達時のユーザー通知不足

**ファイル**: `src/lib/realtime.ts:158-160`

**問題点**:
最大再接続回数に到達した場合、ログに記録されるだけであり、ユーザーには通知されません。

```typescript
} else {
  logger.error(`Max retries (${maxRetries}) reached for gacha:${streamerId}`)
  // ⚠️ ユーザーに通知されていない
}
```

**推奨**:
`onError` コールバックを呼び出し、ユーザーに手動再接続を促す：

```typescript
} else {
  logger.error(`Max retries (${maxRetries}) reached for gacha:${streamerId}`)
  const error: RealtimeError = {
    type: 'connection',
    message: 'Max retries reached. Please refresh the page to reconnect.',
    error: null,
  }
  onError?.(error)
}
```

### 8. コードの複雑性が高い

**ファイル**: `src/lib/realtime.ts:82-188`

**問題点**:
`subscribeToGachaResults` 関数が1つの関数で接続、再接続、エラーハンドリング、ロギング、ステート管理など多くの責任を持っており、テストとメンテナンスが困難です。

**推奨**:
機能を分割することを検討してください：
- 接続管理を別のフックに分離
- 再接続ロジックをカスタムフックに抽出
- エラーハンドリングをモジュール化
